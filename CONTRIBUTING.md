# Contributing

The Pipeline is only useful if it stays accurate. Relocation rules change
constantly, and every checklist item cites an official source with a
verified-on date. Contributors are what keep those dates honest.

You do not need to be technical. A corrected link or a stale date is as
valuable as a new checklist item.

The full guide — who this is for, what to contribute, and the voice we write
in — lives at **<https://ohmoveagain.com/contribute/>**. This file covers the
mechanics.

## Quick start

```bash
gh repo fork 7nolikov/ohmoveagain --clone
cd ohmoveagain
npm install
hugo server          # http://localhost:1313/
```

## Where things live

The project separates **facts** from **words**, and translation depends on
that split holding.

| What | Where |
|---|---|
| Structural facts — URLs, `asOf` dates, persona filters | `data/stages/*.yaml` |
| Translatable strings — labels, notes, source labels | `content/stages/*.md` front matter, under `itemStrings.<item-id>` |
| Calculator baselines | `data/countries.yaml` |
| Fees, forms, offices | `data/fees.yaml`, `data/forms.yaml`, `data/offices.yaml` |
| UI strings | `i18n/en.yaml`, `i18n/ru.yaml` |

Templates merge facts and strings by item ID at build time. Put a URL in the
YAML, not in the prose.

## Before you open a PR

```bash
node scripts/check-staleness.mjs        # source freshness
node scripts/check-i18n-parity.mjs      # EN/RU structural parity
node scripts/check-ui-i18n-parity.mjs   # i18n/*.yaml key parity
node scripts/check-i18n-freshness.mjs   # translations match their source hash
npm run test:unit                       # unit tests
npm run qa:e2e                          # Playwright, needs a running server
```

CI runs all of these plus axe, Lighthouse (desktop **and** mobile) and the
full Playwright matrix. The `quality` check is required to merge.

## Rules worth knowing before you spend time

These are load-bearing. `DECISIONS.md` has the reasoning.

- **Every source needs a URL and a date.** A claim without a primary source
  does not ship. Don't refresh an `asOf` date without actually re-reading the
  source — the date is a promise to the reader.
- **Don't hand-edit `*.ru.md` structure.** Russian content is generated by the
  i18n pipeline. Change the English source; the sync opens a PR. Prose fixes to
  existing Russian strings are welcome.
- **Pin every GitHub Action to a 40-character SHA** (§16). This is now enforced
  by the repository, so an unpinned `uses:` will be rejected.
- **Keep internal links relative.** Use `relURL`/`absURL` in templates and
  root-relative paths in content, so a future base-URL change stays a one-liner.

## Reporting problems

- A wrong or outdated fact → open a **Source correction** issue.
- Something broken on the site → open a **Bug report**.
- A security issue → see [`SECURITY.md`](SECURITY.md). Please don't use a
  public issue.
